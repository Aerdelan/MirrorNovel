MirrorNovel 桌面端 — 版式评审

四版样稿均复用现有设计令牌（森林绿 #3f7d5a / 暖阳橙 #e8943a、卡片 #fffdf9、圆角 8/12/16）。 每版展示的功能页不同，重点看导航结构与信息分区的差别，配色与卡片风格保持一致。

V1 经典固定侧栏打开整版预览
展示页：生成小说。左侧 232px 常驻导航（创作 / 作品 / 账户分组）+ 顶部工具栏 + 底部状态栏。
  • 优点：与现有 Web 端心智一致，学习和迁移成本最低
  • 代价：横向被吃掉 232px，宽内容略拥挤
V2 图标窄栏 + 二级面板打开整版预览
展示页：我的书架。64px 图标栏 + 260px 二级列表（作品分组、最近打开）。
  • 优点：作品多时切换最快，内容区横向空间最大
  • 代价：两级导航需要一次适应，状态略分散
V3 三栏写作工作台（修订版） 推荐 打开整版预览
展示页：作品详情 / 写作。章节栏 + 正文流 + 右侧上下文检查器（伏笔 / 角色状态 / 本章用量 / 质量）。
  • 左侧栏可展开：收起 64px 仅图标（悬停出提示），展开 216px 出完整文字；点「展开侧栏」或 Ctrl+B 切换
  • 菜单与 Web 原版完全对齐，并把「我的」内的模型线路 / 人格 / 设置提到侧栏
  • 优点：长篇写作不用跳页，伏笔与角色状态常驻；右侧可折叠
V4 无边框融合标题栏打开整版预览
展示页：润色（左右对照）。去掉系统标题栏，36px 自定义标题栏 + 自绘窗口控制。
  • 优点：最像原生桌面应用，沉浸感强
  • 代价：需处理拖拽区、macOS 红绿灯留白、最大化吸附等系统细节

技术选型建议（沿用现有技术栈）

桌面外壳：Electron（主进程 Node.js，渲染层直接复用现有 Vue 3 + Vite 代码）
打包：electron-builder（Windows nsis / macOS dmg / Linux AppImage）
复用方式：新增 desktop/ 包，通过 Vite alias 指向 ../client/src，
          views / stores / api / locales 全部复用，仅替换外壳与样式层。

MirrorNovel/
├── client/          # 现有 Web 端（保持不变）
├── desktop/         # 新增：Electron 外壳
│   ├── electron/main.js        # 主进程：窗口、托盘、菜单、自动更新
│   ├── electron/preload.js     # 安全桥：文件对话框、窗口控制、剪贴板
│   ├── src/                    # 渲染层入口（alias 复用 client/src）
│   │   ├── layouts/DesktopShell.vue   # 侧栏 + 标题栏 + 状态栏骨架
│   │   └── styles/desktop.css         # 桌面端样式覆盖（不改 Web 端）
│   └── vite.config.js          # 指向 client/src，产出桌面端专属 bundle
└── ...

备选 Tauri：体积小（约 10MB vs Electron 约 90MB）、内存占用低，但需要 Rust 工具链与额外构建链； 本项目现有生态是纯 Node，Electron 的迁移成本最低。

请你确认的 5 个决策点

  1. 选哪一版为主版式？我的建议：V3 为主（写作台），把 V1 的固定侧栏作为"精简模式"开关；V4 的无边框标题栏可以作为可选项叠加。
  2. 窗口默认尺寸：建议 1280×800 起，最小 1024×680；是否需要"记住上次窗口位置"？
  3. 后端连接方式：默认连线上服务器（可切换自定义地址），还是内置本地服务端进程（需要本机装 MongoDB，成本高）？建议前者。
  4. 离线能力：是否需要本地缓存已生成章节、支持离线阅读与导出？生成本身必须联网。
  5. 打包目标平台：Windows 优先 / 三平台都要？是否需要自动更新（electron-updater）？

实施顺序建议（确认版式后）

  1. 搭 Electron 外壳 + 复用 client/src 跑通登录与生成（验证 alias 复用可行）
  2. 实现 DesktopShell（侧栏 / 标题栏 / 状态栏）+ 桌面端样式覆盖层
  3. 逐页适配 9 个页面（先书架、作品详情，再生成/续写/润色）
  4. 桌面专属能力：托盘、全局快捷键、文件对话框、批量导出
  5. 打包与自动更新
