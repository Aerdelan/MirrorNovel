# MirrorNovel 写作风格与修订能力规划书

编写日期：2026-10-25。适用对象：接手本项目的开发者或 AI 编程助手。

本文同时记录本次初步实施的边界和后续任务。**只有“本次已实施”属于当前功能，后续数据结构、接口和开关均为待实现的设计建议。** 执行前须阅读仓库实际代码，不能把本文中的建议字段当成现有接口。

## 1. 目标与质量要求

在继续使用云端文本 API 的条件下，让作者的写作偏好、本书声线、人物表达和认可样稿可以持续积累、版本化并用于后续写作。更换模型或服务商时，这些资料仍由项目保存。

普通推理请求不会自行修改模型权重。本计划首先通过应用保存的资料与上下文改善稳定性，不把它宣传成已训练出专属模型。

质量目标：

1. 事实、因果、人物选择、信息量和既有章节连续性不能因“去 AI 味”而受损。
2. 作者声线稳定，但句长、段落与节奏允许随场景变化；不同人物保有不同声音。
3. 修订只处理实际问题，已自然成立的原句可以保持原样。
4. 使用者不必理解模型训练、提示词或上下文工程，也能完成样稿认可与偏好确认。
5. 默认路径不增加每章模型调用次数；新增输入预算、调用次数和额外费用必须可见。

不得把禁词数量、随机口语、故意语病、固定段落比例或 AI 检测器分数作为主要质量标准。

### 2.2 本次已实施：参考片段可选输入

- 普通小说和轻小说生成页增加“带入少量参考原文”的选项，默认关闭。
- 请求字段为 `referenceExamplesEnabled`，只有布尔值 `true` 生效；字符串 `"true"` 不生效。
- 仍沿用最多三个参考及账号权限校验，必须是当前账号已有的已蒸馏参考。
- 每个参考最多选一段已有 `keyExcerpts`，每段最多 240 个 JavaScript 字符，最短 40 字符，最多三段、合计不超过 720 字符；跳过重复或无效片段。
- 片段进入作品 `referenceStyleSnapshot`，旧作品不自动查询或补齐新片段，后续修改参考库不会重写旧快照。
- `buildReferencePrompt` 默认 `includeExamples=false`；大纲、蓝图规划继续仅使用分析摘要。小说正文、整本续写、章节续写显式启用示例渲染，但只有原快照已有片段时才有作用。
- 示例仅用于视角、句法、节奏和表达，必须服从当前作品事实、人物、人格与章节任务。提示要求不得复制原句或挪用示例的人物、道具和剧情。
- 没有新增模型调用或向量库。开启后会增加少量输入用量，界面已说明。

此功能不是“用户认可样稿库”：参考片段尚无逐段认可、用途标签、撤销授权或精细检索；这些属于下文任务 A1。初步示例以选中参考的已有提取结果为准，不能宣称已经完成原创性或事实一致性的自动审核。

### 2.3 本次已实施：流式修订保真

- 新增 `server/services/rewriteReview.js`，共享原文对照的终审提示与篇幅校验。
- 流式去 AI 味第二轮不再强制口语化、随机走神、吐槽、填充词或碎片句，改为核对原文事实与作者声线。
- 两轮温度沿用已有非流式保真实现的 0.72 / 0.55；接口地址、任务线路和两轮调用结构保持兼容。
- 终审会同时发送原文和候选稿，比旧流式实现增加一份原文输入；调用轮数未增加，但输入 Token 和费用可能增加。参考示例的输入成本另计，不能把“不增加调用次数”解释为“不增加费用”。
- 候选稿长度相对原文须在 80%–120% 范围。第一轮不合格时发送 `completed` 原文并停止第二轮；第二轮不合格或失败时保留第一轮合格稿。
- `content` 流仍是预览；最终以 `completed.content` 为准，不能将中途片段自动写回作品。
- 此修订入口的最终本地处理不再执行词表去 AI 味和人味注入，仅保留现有格式、标点处理。
- 独立润色默认要求改为服从原文及人格，不把所有作品统一为克制腔或口语腔。
- 主体生成、章节规划、故事状态、连续性审稿、任务租约与模型路由没有重构。

**篇幅检查只能防止明显缩写或扩写，不能证明语义保真。** 语义评测和跨编辑入口统一见 A4 / A5。

### 2.4 本次已实施：认可样稿库（A1，2026-10-25）

- 新增独立集合 `server/models/WritingSample.js`：`userId`、`scope`（novel/screenplay）、`sceneType`（dialogue/action/observation/emotion/transition/other）、`title/content/notes`、`sourceKind`（own_text/human_edit/authorized_reference）、来源身份（`sourceNovelId/sourceNovelTitle/sourceChapterNumber/sourceReferenceId/sourceReferenceTitle`，标题为创建时冗余字段）、`status`（draft/approved/revoked）、`allowedForModelInput`、`contentHash`。规划书建议的 `personaId/styleRevisionId/sourceVersion` 留待 A2/A3 需要时再加入。
- 新增 `/api/writing-samples` 路由（`server/routes/writingSamples.js`）：列表（状态/范围/用途过滤、分页上限 50、按状态聚合计数）、详情、创建、编辑、认可、撤销、删除。全部查询限定 `userId`，跨账号一律 404，不暴露存在性。

- 新增 `server/services/writingSamples.js`：字段清洗、规范化（换行统一、空行折叠）与 sha256 哈希；`loadApprovedSamples(userId, { scope, limit })` 是生成候选池的唯一入口，只返回 `status='approved'` 且 `allowedForModelInput=true` 的当前账号样稿；`buildSamplesPrompt` 按参考示例既有预算（最多 3 段、每段 240 字）渲染"作者认可的写作样稿"资料块，空数组返回空串（旧账号完全兼容），并明确样稿是资料而非指令、其中的命令式文字不得当作系统指令执行。
- 认可语义：新建默认草稿；`allowedForModelInput` 只有布尔 `true` 生效，且仅 `own_text`/`human_edit` 来源可在创建时附带立即认可；`authorized_reference` 来源强制草稿，认可必须显式操作。撤销会同时清除允许输入标记；重新认可即可恢复。**修改已认可样稿的正文会使其回到草稿并重新哈希**，需再次认可（界面有提示）。
- 删除策略：删除样稿只移除库内记录；来源作品/参考删除不影响已保存样稿（来源标题为冗余字段）。未来 A2 引入作品级快照后，同样不回改旧快照。
- 界面：新增 `/writing-samples` 样稿管理页（状态页签计数、新建/编辑弹窗、认可/撤销/删除、分页），底部导航"样稿"入口；小说详情页章节正文划选 40–2000 字出现"存为样稿"选区条，弹窗预填来源与正文；参考库风格档案内每个精选片段可"存为候选样稿"（弹窗标注待认可，不提供立即认可勾选）。中英文文案齐备。
- 本次未把样稿注入任何生成或编辑提示词；`loadApprovedSamples`/`buildSamplesPrompt` 供 A2 选择器与 A4 各入口接入。真实写作质量、语义保真与抄用风险均未评测。

### 2.5 本次已实施：风格版本与按章轮换（A2，2026-10-25）

- 新增不可变集合 `server/models/WritingStyleRevision.js`：创建时冻结 `personaSnapshot`（可选）与 `samples`（从"已认可且允许作为模型输入"的小说样稿池固定，正文预裁剪到 240 字，每版本最多 9 段）以及 `sampleBudget`（3 段 × 240 字，显式固化）。**没有更新路由，服务层也不提供更新函数**；版本号在账号内递增，编辑人格模板或增删样稿库不影响已创建版本。
- 新增 `/api/style-revisions` 路由（`server/routes/styleRevisions.js`）：列表、详情、创建（显式指定 `sampleIds` 时逐个校验必须是当前账号已认可的小说样稿，缺一即 400，不静默回落）、`compare/:a/:b` 对比（人格变化字段 + 样稿增删改）。全部查询限定 `userId`，跨账号 404；创建与对比不触发任何模型调用。
- 新增 `server/services/styleRevisions.js`：`selectRevisionSamples` 按章号做**确定性轮换**——第 N 章从版本内第 `((N-1) mod 总数)` 段开始环绕取 `min(3, 总数)` 段，同章恒定、跨章轮换、可解释、可回放，杜绝"每章反复同一段示例"与"随机改变风格"两个极端；`buildRevisionSampleBlock` 返回提示词块与抽样记录；空快照/空候选返回空块（正常降级）；注入边界文案与 A1 渲染器共享同一常量。
- 作品采用：`PUT /api/novel/:novelId/style-revision` 把版本冻结复制进 `novel.styleRevisionSnapshot`（含 `adoptedAtChapter` = 最高章节号 + 1），生成链路**只读快照、不回查版本集合**——任务期间版本固定；回退 = 再次采用旧版本，历史版本从不改写。采用/停用受忙碌守卫（`rejectBusyNovelMutation`）保护，生成运行中返回 409。
- 生成链路接入（仅小说正文三条主链路）：`/generate` 建书时若样稿池非空自动冻结 v1（人格快照一并固定，失败仅降级不阻断建书）；`/generate` 与 `/continue/:novelId` 的章节循环、`/continue-chapter` 单章续写在系统提示末尾按章号注入轮换块（前缀缓存友好），并把抽样记录（revisionId/version/sampleIds/titles/reasons）写入 `chapters[].styleSamples`。样稿块优先级低于作品事实、人格与本章任务；"导入续写"链路本次未注入（A4 统一处理）。

### 2.6 本次已实施：从修改中积累偏好（A3，2026-10-25）

- 新增 `server/models/WritingFeedback.js`：一次人工修改的记录（作品 + 章节 + 修改前/后文本、哈希、场景类型、八种理由、备注）。只在作者显式点击"记为写作偏好"时创建；同账号 + 同章节 + 同原文/修改稿哈希幂等返回已有记录。哈希按完整文本计算，存储正文超出 4000 字时显式截断并保留完整长度。
- 新增 `server/models/WritingPreference.js`：经作者确认的长期规则（statement 10–300 字、理由、适用范围）。`novelId=null` 表示账号所有作品，带 `novelId` 只影响该书——其他书的偏好绝不会进入本书快照。状态机 `candidate → active → paused`（可重新启用、可删除）；**只有 active 偏好会在采用风格版本时冻结进快照**，候选与停用中的偏好永不生效。
- 提炼（任务 4/7）：`POST /api/writing-feedback/:id/distill` 是显式操作（reasoning 线路，一次调用，弹窗确认费用提示）。服务层强制四道闸：`仅纠错/仅本次修改` 直接 400（任务 3，不产生跨作品规则）；修改稿已不在章节当前内容中 → 409（"不能把已过期改动作为最新偏好"）；重复提炼幂等返回已有偏好且不再调用模型；模型不可用 → 500 通用错误，反馈保持可复用，正文保存完全不受影响。提炼输出经 JSON 解析与校验（太短/照抄原文 → 502），**只产出 candidate**，确认必须由作者显式操作，任何代码路径都不写全局写作人格（任务 6）。
- 生成接入：`freezeRevisionSnapshot` 在采用时把生效偏好（账号范围 + 本书范围，最多 5 条 × 200 字）冻结进快照；`buildRevisionSampleBlock` 把偏好块渲染在逐章轮换样稿块**之前**（逐章逐字节一致，保住前缀缓存），并在章节 `styleSamples` 记录中追加 `preferenceIds`。停用偏好不影响已采用快照，重新采用才生效（版本固定语义不变）。
- 界面：章节编辑保存成功后出现**非打断的行内提示条**（15 秒自动收起），点击才打开"记为写作偏好"弹窗（修改前后对照、理由、场景类型、备注，不记录什么都不保存）；样稿页新增"写作偏好"面板——修改记录（理由/场景徽标、前后对照、提炼按钮带费用确认、删除）与偏好规则（状态/范围徽标、证据片段、确认/放弃/停用/启用/删除、手动添加默认账号范围）。
- 未做：提炼候选的冲突自动检测（界面展示既有规则供作者自行判断）、按场景检索偏好、剧本侧反馈入口、真实模型盲测。"模型不可用不影响保存""未确认偏好不生效"均已有集成测试覆盖。

### 2.7 本次已实施：同一份风格上下文（A4，2026-10-25）

- 新增无网络副作用的共享构建器 `server/services/styleContext.js`：`buildStyleContext(snapshot, purpose, { chapterNumber })` 从作品冻结快照读取资料，明确区分三种用途——`prose`（写新正文：偏好块 + 逐章轮换样稿块，A2/A3 行为）、`revise`（修订现有文本：偏好块 + **修订边界样稿块**——"原文是唯一的事实基准，样稿只校准表达方向、不得改动事实因果与人物选择、只处理明确指出的问题" + 修订纪律注记）、`plan`（规划结构：不注入，维持"规划只用分析摘要"的既有决策）。快照为空（旧作品/未采用版本）一律返回空块，调用方按旧路径继续。
- 入口接入清单（按规划书 A4 表逐项审查 `buildPersonaPrompt`/`buildReferencePrompt`/`processChapter`/`humanizeRewrite` 调用点）：
  - 新建正文、整本续写、章节续写：已在 A2/A3 经 `buildRevisionSampleBlock` 注入，A4 起统一归入 `prose` 用途语义。
  - **导入续写：刻意不注入**（原声线优先，不套账号默认风格）——路由内有显式注释，集成测试有源码级守护。
  - **`/deslop` 与 `/deslop-stream`**：注入修订上下文，两轮改写共用同一系统提示；无 novelId 或作品无快照时保持旧行为。
  - **`/polish`**：主润色调用注入修订上下文；诊断调用（分析类）保持干净。
  - **连续性审稿与定点修订**：定点修订（专家修订阶段）注入修订上下文；审稿输出为评审意见（非正文），不注入。
  - **`/optimize` 全文调优**：任务开始时从加载的 novel 文档构建一次上下文，逐章复用（全任务固定一个版本），仅注入章节修复调用，全文分析保持干净。
  - **`editorialEngine.js`**：`runEditorialPipeline` 接受 `styleContext` 参数并追加到每个阶段的系统提示与精简重试提示；`/editorial-stream` 与整本编辑任务各自构建一次传入（整本任务全任务固定一个版本）。
- **editorialEngine 去随机作者（规划书点名项）**：persona 阶段改为 `persona || null`——只使用作品/账号绑定的真实人格，**不再随机生成"教育/年龄/模仿乌贼/习惯/缺点"的假作者**；无人格时不注入作者约束（`personaConstraint(null) === ''`）。精简重试提示删除"加入废信息和角色走神""叙述口语化"等全局噪声指令，改为"句式有长短变化，服从原文与作者声线"。随机人格生成函数保留导出但不再被流水线调用。
- **剧本**：延后。剧本生成已有自身人格快照（`Screenplay.writingPersonaSnapshot`）；剧本范围的样稿/版本在 A2 中预留 scope 但未建创建入口，待剧本侧样稿与版本功能建立后另行接入，不把小说叙述风格搬成场面说明。
- 前缀缓存：偏好块稳定、prose 样稿块逐章轮换但同章恒定、revise 块在单任务内恒定；无重复注入同一份长提示的实现。Token 用量继续由 streamGenerate 的 usage 账本按角色记录，无以字符数冒充账单的路径。
- 未做：按场景类型筛选样稿、人物声音档案（角色级声线约束）、剧本侧上下文、真实模型盲测。"仅检查提示词关键词"不作为生效证明——集成测试通过捕获实际发给模型的 system/prompt 断言。

### 2.8 尚未实施

按场景检索样稿与偏好、人物声音档案、剧本侧风格上下文、真实模型盲测，以及训练数据导出或模型微调。A1–A4 已实施（见 2.4–2.7）。

## 3. 后续系统如何组织

用四层资料组织写作：

| 层级 | 保存内容 | 边界 |
| --- | --- | --- |
| 账号的长期偏好 | 经作者确认的通用写作倾向 | 不自动覆盖所有已创建作品 |
| 本书风格版本 | 叙事视角、距离、语言气质、六轴、认可示例 | 创建或显式切换时固定快照 |
| 人物声音 | 背景、说话目的、措辞边界、关系差异 | 不把所有角色改成叙述者的口吻 |
| 本章 / 本场任务 | 事件、压力、信息、关系变化和执行目标 | 可以调整局部节奏，不推翻全书声线 |

风格来源冲突时，先守住原文事实和当前用户的明确任务；表达选择再按本书已确认风格、人物声音、经确认的偏好、相关样稿、通用工艺指南处理。参考作品始终不能接管本书人物和剧情。

作者可能主动改变视角或风格。这应通过明确的修订意图和新版本实现，不能误判成必须恢复的“漂移”。

## 4. 分阶段执行清单

依赖顺序：**A1 → A2 → A3 → A4 → A5**。可在每个阶段后独立交付和验收。A6 为可选探索，不能作为前面阶段的前置依赖。

### A1：认可样稿库（优先）

目的：让作者能明确告诉系统“这个片段值得学，学它的哪一方面”。

建议新增独立 `WritingSample` 集合；不要把无限量正文塞进 `WritingPersona` 文档。建议字段：

```text
userId
novelId? / sourceChapterNumber? / sourceVersion?
personaId? / styleRevisionId?
scope: novel | screenplay
sceneType: dialogue | action | observation | emotion | transition | other
title / content / notes
sourceKind: own_text | human_edit | authorized_reference
status: draft | approved | revoked
allowedForModelInput: boolean
contentHash / createdAt / updatedAt
```

任务：

1. 从章节选中文字加入样稿，或手动粘贴；保存前展示具体片段、来源、使用范围和用途标签。
2. 作者明确认可并允许作为模型输入后，才进入生成候选池。默认不扫描全库，也不自动认可所有生成结果。
3. 已有参考的 `keyExcerpts` 只能作为待认可候选，不能一键迁移成全部已批准。
4. 提供查看、修改、撤销、删除；删除样稿或源作品后的快照策略要明确。
5. 普通调用只读当前账号的已批准数据，禁止跨账号推荐和共享。
6. 对重复点击使用来源版本与内容哈希做幂等处理，并设置数量、长度和分页上限。

验收：草稿和撤销样稿不被注入；跨账号请求返回无权限或不存在；重复提交不产生重复记录；删除或撤销后的行为有测试。旧账号没有样稿时完全兼容。

> 状态（2026-10-25）：A1 已按上节 2.4 实施并通过验收测试。实现与建议字段的差异：`personaId/styleRevisionId/sourceVersion` 未加入（A2/A3 需要时再加）；来源身份用 `sourceNovelId/sourceReferenceId` 表达。任务 2 的"生成候选池"已实现为 `loadApprovedSamples` 服务门，但尚未接入任何生成入口（属 A2/A4）。

### A2：风格版本与按场景选择样稿

目的：同时实现稳定性、可回退和有限输入预算。

建议新增不可变 `WritingStyleRevision`，引用人格和已认可样稿，并保存完整的生效配置。`Novel` 记录版本 ID 与必要快照；当前 `writingPersonaSnapshot` 保留为旧数据兼容入口。

任务：

1. “创建新版”生成新版本，不覆盖旧版本；支持比较和回退。
2. 新偏好不会静默影响已有书籍。作品明确采用新版后，记录生效章节；生成中的任务继续使用启动时版本。
3. 样稿按适用范围、场景类型、语言与风格版本筛选，初期使用可解释的本地规则，不强制引入向量库。
4. 初期保持最多三段、总计 720 字符的预算；预算如需增加，作为显式配置并评测，不能每章自动膨胀。
5. 对抽样结果记录样稿 ID、版本和选择原因；不要记录密钥。
6. 仅按主题相似度检索不够：同为雨夜场景也可能属于不同叙述声线，不能把剧情相似作为唯一标准。
7. 避免反复使用一个结尾、比喻或段落模板；轮换规则必须稳定、可追踪，不能随机改变风格。

验收：同一任务续接时版本不变；改模板不影响旧书；同一账号两本不同风格作品不串样稿；无适合样稿时正常降级；不增加默认模型调用次数。

> 状态（2026-10-25）：A2 已按上节 2.5 实施并通过验收测试。与建议的差异：任务 3 的"按适用范围、场景类型、语言与风格版本筛选"暂按版本内确定性轮换实现（场景类型筛选属 A4 入口细化）；任务 5 的抽样记录落库到 `chapters[].styleSamples`；剧本版本入口未开放（模型已预留 scope）。

### A3：从修改中积累偏好

目的：记住作者认可的修改理由，而不是只记住字面替换。

建议新增 `WritingFeedback` 与 `WritingPreference`，前者存一次修改及其用途，后者存经过作者确认的长期规则。

任务：

1. 章节保存后提供可选的“记为写作偏好”；默认只保存正文和现有历史，不自动学习。
2. 记录原文、修改稿、原文版本、场景类型、作品和理由。理由可选择重复信息、人物声音、视角、节奏、情绪表达、语言密度、仅纠错或仅本次修改。
3. “仅纠错”和“仅本次”不能变成跨作品规则。例如删掉一句不等于偏爱所有短句。
4. 如需 AI 提炼候选偏好，做成显式操作；使用现有推理线路，说明额外调用，不在每次保存时自动请求。
5. 候选偏好展示证据片段、适用范围和可能冲突；作者确认后加入新风格版本，允许停用和回退。
6. 不从“没有编辑”“点击保存”或模型自评分推断作者认可。
7. 多人或多窗口修改应检查源版本，重复提炼要幂等；不能把已经过期的改动作为最新偏好。

验收：修改正文仍能独立完成；模型不可用不影响保存；未确认偏好不生效；只适用于某本书的偏好不影响其他书；模型提炼结果不能直接更新全局人格。

> 状态（2026-10-25）：A3 已按上节 2.6 实施并通过验收测试。与建议的差异：AI 提炼按单条反馈逐条进行（未做批量提炼）；提炼候选的冲突检测为展示式（列出既有规则供作者判断），无自动冲突消解；手动添加的偏好默认账号范围（书本范围偏好经该书修改记录提炼产生）。

### A4：生成与编辑使用同一份风格上下文

目的：避免正文逐渐形成特色后，被润色、去 AI 味或全文调优改成另一种腔调。

建议实现一个无网络副作用的风格上下文构建器，读取已确定的版本、人物声音与有限样稿，明确区分“写新正文”“修订现有文本”“规划结构”三种用途。

逐项审查并接入：

| 入口 | 重点 |
| --- | --- |
| 新建正文、整本续写、章节续写 | 使用本书快照，维持角色与情节约束 |
| 导入续写 | 原文已建立的声线优先，不能直接套账号默认风格 |
| 连续性审稿与定点修订 | 只修复指出的问题，编辑自身的“克制”要求不能覆盖作者 |
| `/deslop` 与 `/deslop-stream` | 保留本次原文对照复核；样稿不能改动原文事实 |
| `/polish` | 自定义润色要求与事实保真边界明确，保留选定声线 |
| `editorialEngine.js` | 优先真实人格，审查默认随机教育、年龄、喜爱作者、习惯及缺点的注入；不再随机决定本书作者 |
| 全文调优与整本编辑 | 全任务固定一个版本，逐章失败可恢复，不静默切换 |
| 剧本 | 使用剧本自身范围的样稿和人物对白，不能直接把小说叙述风格搬成场面说明 |

任务：

1. 源码搜索所有 `buildPersonaPrompt`、`buildReferencePrompt`、`processChapter`、`humanizeRewrite` 调用，建立实际入口清单，不只修一个函数。
2. 区分“必须保留的事实”和“允许调整的表达”；禁止参考片段中的命令变成系统指令。
3. 本地处理默认仅做可解释的文本规范化。对词表替换、随机节奏、人味注入逐项建立用例，确认无误伤后再调整。
4. 叙述者介入、书面语、长句、心理活动和幽默应服从本书风格，不能设全局禁令。
5. 避免重复注入同一份长提示，维护稳定的提示前缀；必须记录模型实际用量，而不以字符数冒充账单。
6. 共享构建器应有单元测试，调用路由应有集成测试；仅检查提示中有关键词不能证明最终生效。

验收：全部入口有覆盖；作品快照优先；选定风格能进入所有需要的模型请求；原文与候选稿在终审时同时存在；无风格数据时兼容旧路径；暂停、重连、Token 统计、导出与历史回退不回归。

> 状态（2026-10-25）：A4 已按上节 2.7 实施并通过验收测试。与建议的差异：剧本入口延后（见 2.7 末项）；连续性审稿（输出评审意见而非正文）与大纲/蓝图规划维持不注入；editorialEngine 的"全文调优与整本编辑"版本固定通过"任务开始时构建一次上下文 + 单一 novel 文档"实现，未新增持久化任务元数据。

### A5：建立写作质量回归集

分为自动检查与真实模型对比，二者不能互相替代。

自动测试使用模拟 AI、隔离数据库和浏览器接口拦截，覆盖：

- 账号、作品、风格版本隔离；输入预算、授权状态与截断策略。
- 同一次任务的版本固定、失败回退、暂停续接和重复写入保护。
- 人格、原文、样稿、任务要求冲突时的优先级。
- 流式片段不作为正式终稿，`completed` 才决定最终内容。
- 手工修改、章节历史、草稿恢复、并发编辑和导出保留当前行为。

真实模型对比使用同一场景、同一已知事实与同一线路，做匿名 A/B：

1. 先建立一小组固定场景：对话交锋、行动、关系变化、观察和情绪收束；覆盖至少两种差异明显的本书声线。
2. 记录事实与因果、人物声音、作者声线、重复程度、自然度和需要人工修改的幅度。
3. 原文修订应标出必须保留的事件和信息，不只看长度比例。
4. 同时记录调用次数、Token、等待时间和失败率；流畅度包含界面不卡顿和文本衔接自然两个方面。
5. 由作者盲选为主；评审模型只能辅助说明证据，不以自身审美自动推翻作者风格。
6. 在用户选定线路、测试样本和费用预算后执行真实调用，不擅自使用仓库密钥跑批。

发布门槛：自动测试通过，且小范围真实对比没有出现事实保真或连续性明显退化；是否扩大使用由测试证据决定。未做真实对比时，交付必须明确说明，不能声称“写作质量已提高”。

> 状态（2026-10-25）：A5 自动检查部分已实施——清单逐项映射见 `docs/QUALITY_REGRESSION.md`（含新增 `tests/qualityRegression.test.js`：重复写入守卫、人格/样稿/偏好组合优先级、预算截断汇总）。真实模型对比的**工具**已就绪（`server/scripts/qualityAB.mjs` + 场景模板 + `npm run quality:ab`），安全守卫已验证（无 `--yes` 拒绝调用、不读仓库密钥、密钥不落盘）；**真实对比尚未执行**，需用户按该文档选定线路/场景/预算后自行触发。发布门槛未达成前，不做任何“写作质量已提高”的声明。

### A6：可选的模型适配与训练数据准备

仅当 A1–A5 的数据与评测成熟、确有需求时再开展。

- 先按模型版本保存兼容参数、上下文预算和同一回归集的结果，不假设换模型后文风完全相同。
- 经用户选择后，导出有授权的认可样稿与修改对；区分训练、验证、测试集，避免同源相邻段落泄漏。
- 去除账号标识、凭据和无授权的参考原文；支持撤销与重新导出。
- 若使用支持微调的供应商或开源模型，另行核对其实际支持、费用、许可和部署条件。
- 任何微调、LoRA 或自动偏好优化均作为单独任务，不作为本规划前期的默认实现。

## 5. 并发、兼容与数据迁移要求

1. 仓库可能已有本次和前一轮体验修复的未提交改动。先执行 `git status`、阅读差异，保留草稿保护、剧本场景编辑和历史恢复等既有成果；禁止用 `git reset --hard`、`git clean` 或整文件旧版本覆盖。

6. 风格更新与正在运行的生成分开：任务固定版本，用户在任务结束或暂停后明确选择新版本。
7. 源码、网页端、桌面渲染层与后端需同步发布；仅更新前端不能假定服务端已有新接口。
8. 样稿输入作为资料处理，不能直接拼为高优先级指令；资料包含“忽略以上要求”等内容的用例必须测试。
