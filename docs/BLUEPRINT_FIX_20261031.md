# 初始三级蓝图修复（2026-10-31）

## 真实现象与证据范围

桌面端1.1.3创建30万字、每章5000字、现实职场题材新作品时，两次在“生成初始蓝图”后收到“模型返回的三级蓝图结构不完整”，尚未生成正文。

这两次线上响应未保存原始模型正文，不能事后断言某一个机制就是当次失败的唯一原因。本次已在旧代码中复现并修复以下具体缺陷：

1. **流读取丢尾帧。** 流按换行拆包，却没有处理EOF时剩余的最后一行；而且只接受`data: `，忽略合法的`data:`。兼容网关的尾帧没有换行时，闭合JSON、`finish_reason`和`usage`可能被丢掉，连自动续写都无法触发。
2. **错误提取内部篇章。** 根JSON截断或语法失败后，原解析器会继续从内部的`{`开始尝试，可能将`{"title":"夜班账",...}`当成整份蓝图。原始JSON语法错误因此被掩盖为“缺少蓝图顶层结构”。
3. **续写去重破坏结构。** JSON截断续写曾共用正文的后缀/前缀去重；前段末尾和续写开头各自必需的`}`可能被当重复字符删除。续写提示也只有末尾片段，丢失原始任务的完整字段要求。
4. **容错替换误改字符串。** 原解析器用全局正则清理尾逗号，会改掉JSON字符串内的字面`,}`和`,]`，破坏故事内容。

新增回归测试先在旧实现复现失败，再对修复实现验证；旧版解析器对比脚本也确认了内部篇章误提取和字符串误改。

## 修复后的行为

- 所有帧使用同一处理函数，接收`data:`带/不带空格、CRLF和EOF尾行；尾帧的闭合字符、停止原因、实际用量都被保留。
- 三级蓝图使用独立完整文档解析器，支持代码围栏、前后说明、数组及`blueprint/storyBlueprint/data/result`包装，不提取未闭合根对象里的篇章碎片；尾逗号处理只发生在字符串之外。
- 蓝图明确使用JSON续写模式，保留结构字符，带回原始任务和JSON首尾上下文。普通小说正文的去重行为不变。
- 格式或字段校验失败时，至多自动发起一次修复逻辑调用；空输出、仍被截断或超过修复输入预算时直接给出明确错误。两次逻辑调用可能各自包含原有网络重试/截断续写，所有实际用量累计记录。
- 修复后的蓝图仍须经过原有篇章覆盖、阶段、标签、人物和滚动执行卡校验；没有降低内容标准，没有本地伪造完整蓝图。
- 错误区分`invalid_json`、`missing_fields`、`output_truncated`、`contract_invalid`，携带错误编号、输出长度/哈希、结束原因、续写轮次和缺失字段。普通后端日志不输出密钥、模型思考或故事原文。
- 前端收到蓝图内容后显示接收字数，避免输出阶段仍一直显示“深度思考”；显示修复进度及失败调用用量。

## 部署

核心修复须一起更新并重启Node后端：

1. `server/routes/novel.js`
2. `server/services/aiService.js`
3. `server/services/blueprintPayload.js`（新增，不能漏传）

后端更新包内保留`routes/`和`services/`相对路径，应在服务器的`server`目录应用。先备份现有同名文件，再更新和重启服务。无需数据库迁移或安装新依赖。

前端进度显示涉及`client/src/views/GeneratePage.vue`及中英语言文件；Web端需重新构建发布，桌面端需重新打包才会显示新进度提示。现有桌面端可以使用更新后的后端核心修复。

本次未修改远程服务器、未重新发起收费蓝图请求。部署后应按原30万字参数真实复测；若仍失败，先用错误编号核对日志的`reason/finishReason/outputChars/stitchedRounds/missingFields`，避免盲目连续重试。
