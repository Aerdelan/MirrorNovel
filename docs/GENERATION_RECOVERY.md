# 生成卡顿恢复与重新编辑

生成按钮下方和生成结果弹窗内均提供「检测卡顿」。检测查询后台的持久化任务与租约，不会因为模型长时间思考或网络断开就断言生成已经停止。

- 后台仍运行：显示状态，可打开对应作品，或点击「暂停任务并恢复页面」。收到后台停止确认前不解锁重复生成。
- 后台任务已停止、服务器重启后租约过期：恢复可编辑表单，保留填写信息、原书章节与断点草稿。
- 暂时连不上后端：允许先恢复页面编辑，保留待核对任务；再次确认后台状态后才允许生成。
- 桌面关闭、页面刷新或创建成功响应丢失：按账号保存本次输入和请求标识，重新打开页面后可检测并找到对应作品。本地存储不可用时显示提示。

书架新增「重新编辑」。点击后回填建书时的题材 SKU、频道、人物、世界设定、大纲、蓝图、模式、总字数、每章字数、专家模式、人格选择、参考资料和结构、联网设置与链接。编辑后生成一本新书，原书和章节不被覆盖。旧书没有完整初始快照时，根据现有数据回填并明确提示核对缺失设置。

服务端新增 `Novel.generationInput` 冻结快照与账号内唯一的 `generationRequestId`，以及以下受账号鉴权保护的接口：

- `GET /api/novel/:novelId/generation-input`：初始输入；`exact` 区分冻结快照和旧书推断。
- `GET /api/novel/generation-request/:requestId`：在创建响应丢失后查询作品与任务状态；其他账号查不到该作品。
- `GET /api/novel/generation-job/:novelId`：增加 `active`，明确区分活跃租约与过期后等待用户恢复的 queued 草稿。

快照仅保存创作参数，模型线路、API Key 和请求头不进入快照。检测不调用模型。桌面包只包含客户端，本功能需要同步更新业务后端；不会自动部署线上。

回归覆盖：服务端输入冻结与同请求防重、跨账号查询、真实 Mongo 过期租约草稿保留；前端账号草稿隔离；桌面浏览器的「书架回填 → 非终态断流 → 健康任务保护 → 断网恢复 → 刷新 → 按请求找回 → 编辑后新建 → 主动暂停」完整流程。

同轮修复书架续写弹窗的 `{seconds}` 占位符：传入服务端思考事件中的 `elapsedMs` 对应秒数，每章重置并忽略无效值。浏览器回归实际校验「已思考 639 字 · 已用 33 秒」，不允许残留占位符或 NaN。

本轮验证：服务端 305 项、隔离 Mongo 集成 16 项、前端 51 项、桌面浏览器 4 项通过；Web、桌面渲染层构建与国际化检查通过。浏览器回归使用 `--test-concurrency=1`，避免本机资源不足导致多个 Chrome 同时启动时崩溃。没有调用真实模型或部署服务端。
