## 邮箱验证码的 429 调整

取消发码、改密提交共用的“每个 IP 每小时 10 次”额度，也不再将注册提交和登录共用计数。提交注册和新密码通过每码猜测次数防护，即使发邮件触发限流，已收到的验证码仍可正常提交。

同一邮箱、同一用途默认 30 秒可以重发；冷却期重复请求返回正常的 `200 + cooldown + retryAfter`，保留原验证码，不重复发邮件。返回剩余等待秒数，不会每次点击重新等满 30 秒。修改邮箱会清除上一邮箱的本地倒计时，后台仍独立校验每个邮箱。

发邮件只保留每个 IP 每 15 分钟 300 次的宽松保护。登录失败按邮箱和 IP 分别计数，默认每 15 分钟 30 次；另保留 IP 每 15 分钟 300 次失败的总保护，成功登录不累计。上述登录计数不影响发码、注册和改密。

真正超限时统一返回 `429`、`Retry-After` 和 JSON `retryAfter`。网页、桌面及移动端都按服务端时间更新发码按钮，验证码输入和提交继续可用，不自动重试发邮件；同时支持代理返回的 HTTP 日期格式 `Retry-After`。

重发间隔、每码尝试次数及批量发信阈值可通过 `EMAIL_CODE_RESEND_SECONDS`、`EMAIL_CODE_MAX_ATTEMPTS`、`EMAIL_CODE_IP_LIMIT` 调整，缺省分别为 `30`、`10`、`300`。

在相应目录执行：

```text
server:  npm test
client:  npm test
client:  npm run check:i18n
client:  npm run build
desktop: npm run build
app:     npm run build:h5
```

页面测试依赖已安装的 Chrome 和 `server` 中的 Playwright，使用本地生产构建和模拟 API。覆盖网页、桌面渲染层及移动 H5；接口测试隔离 SMTP 和数据库，并另用真实 Mongoose schema 检查密码哈希、验证码查询及索引定义。

本次结果：后端 254 项、客户端 41 项全部通过；网页和桌面渲染层共 18 个交互场景、移动 H5 4 个交互场景全部通过，包含普通冷却、真实 429、输入和提交不受发码限制、不同邮箱互不影响等回归。网页、桌面渲染层、移动 H5 的生产构建及客户端中英文文案检查通过。

## 发布与边界

需要部署后端和网页构建，桌面客户端、移动客户端也需重新构建分发，旧安装包不会自动获得页面修复。

后端启动时等待验证码的稀疏唯一索引创建完成；旧验证码无需清库。验证码用途、10 分钟有效期和账号密码哈希方式保持兼容。

尚未连接生产 SMTP、生产数据库，也未在客户原设备、真实 Electron 窗口或 Android/iOS 软键盘上复现。原生 `alert` 是代码中明确的交互阻塞点；已验证移除后页面可点击和输入，客户原设备的焦点异常仍需更新后确认。
