## 线路与任务

- 所有文本功能沿用目标的 `outline / writing / reasoning / polish` 四角色线路。参考蒸馏与结构分析使用推理角色；剧本大纲与正文分别使用既有大纲、正文角色。
- 桌面流式请求与后台剧本批量请求都会转发当前账户的 `x-mn-model-config`，不会在数据库任务记录、参考或作品中保存该密钥。
- 新任务复用 `GenerationJob` 的数据库独占租约、心跳和 fencing 校验；剧本另有 `GenerationTask` 进度记录及活动任务唯一索引。服务重启保留已完成内容，把没有有效租约的剧本任务标为可继续，不自动使用已消失的本机密钥重开请求。
- 参考长文按开头、中段、结尾均匀取最多二十段，每段约两万字，多个分析报告再合并。长文并非逐字全部送给模型。
- 既有账户计费路径未替换，没有引入积分扣款。新剧本记录项目 Token 用量；现有管理端的小说 Token 报表仍按小说账本统计。

## 导入上限

文本文件上限 10 MB，EPUB / ZIP 文件上限 50 MB，展开累计上限 100 MB；每包最多二十本，最多一万条目录项。参考库文本预算最多五百万字符，超出预算会抽样保留不同位置的正文。ZIP 当前仅支持 ZIP 格式，不支持 RAR / 7z。导入不执行 HTML 脚本、不向磁盘解压用户文件。

## 部署

安装包：`desktop/release/MirrorNovel Setup 1.1.0.exe`。
更新包：`.tmp/MirrorNovel-creative-migration-20261014.zip`。

更新包包含当前版本服务器代码及锁文件、用户网页 `client/dist`、管理网页 `admin/dist` 和本说明。没有 `.env`、用户数据库、Cookie、API Key、本机依赖或对比项目的运行数据。

1. 在维护窗口暂停生成，备份当前服务目录与数据库。
2. 将更新包中的 `server` 文件覆盖服务器对应目录，保留服务器自己的 `.env`、Cookie 和其他运行数据。不要把另一个项目的配置复制过来。
3. 服务器 Node.js 需至少 **20.19.0**（新 EPUB 解析依赖要求），建议使用已配置的 Node 22 或更高版本。
4. 在服务器 `server` 目录执行 `npm ci --omit=dev`，然后用原来的 PM2 / systemd / 启动方式重启本服务。不要把这些命令误在另一个同名项目执行。
5. 若使用网页端，将 `client/dist` 和 `admin/dist` 发布到原来的静态站点目录；路由继续使用现有 SPA 回退配置，API 仍走原来的后端代理。桌面端需要本次新安装包，因为旧安装包没有新增界面。
6. 无需删除或转换现有小说。MongoDB 启动时创建新增的参考库、剧本、任务和章节版本集合及索引；服务数据库账号需有建索引权限。既有作品可直接进入剧本改编，历史版本从本次更新后的修改开始积累。
7. 新版桌面默认沿用当前正式后端地址。服务器更新后登录，在侧栏打开“参考上传与蒸馏”或“AI剧本”。管理员如需生图，在管理端模型配置页设置生图地址、模型和密钥；未配置时可正常使用文本剧本。

这次在本地完成代码迁移与构建，没有替用户操作远程服务器部署。
