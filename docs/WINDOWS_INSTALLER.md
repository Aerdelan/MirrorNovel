# Windows 安装进度停滞排查与 1.1.2 修复

用户反馈为安装进度接近完成时卡住。本轮没有取得该次安装的现场日志，因此不能断言只有一种原因；已修复安装流程中能造成同类表现的路径。

## 改动

- 用自带 PowerShell 脚本读取进程的完整可执行路径，替换 electron-builder 默认没有超时的 `cmd / tasklist / taskkill` 检查。每次外部检查设置 15 秒无响应超时；被策略拦截、无法确认权限或关闭失败时明确退出。
- 只处理所选安装目录及注册的上一安装目录中的程序，不按程序名关闭其他目录的副本，也不关闭其他 Windows 会话的程序。
- 交互安装发现程序运行时先提示保存内容；静默安装返回退出码 2，让调用方先关闭程序再试。
- 主程序增加单实例与 `--quit-for-update` 退出协议，支持关闭仅留在托盘中的新版本；旧版本走有界的关闭与路径校验后停止流程。
- 旧版卸载失败时不在静默升级中打开等待确认的对话框，明确返回错误。交互模式的错误框置前，避免被安装窗口遮住。
- 显示安装详情，记录检查、完成和旧版清理失败信息到 `%TEMP%\MirrorNovel-install.log`。安装完成后不再默认启动应用；用户从快捷方式启动即可。
- 显式保留应用数据；不清理登录、模型线路、IndexedDB 等用户配置。退出可被未保存编辑的提示取消时，不提前关闭本地 API 代理；托盘重开窗口复用同一本地端口。

## 本轮验证

- 6 项自动测试通过：主进程单实例与退出协议、取消退出后保留服务、托盘重开复用端口，以及真实 Windows 进程按路径检查/停止。进程测试同时启动两个同名测试程序，确认另一目录的副本仍在运行。
- `node desktop/scripts/test-installer.mjs` 使用独立随机产品标识、独立注册表项和小型惰性测试程序，验证真正的 NSIS 安装/卸载链路：中文带空格路径全新安装、旧默认脚本升级到新脚本、运行中程序拦截、锁文件失败、解除锁后的升级重试、隔离卸载。
- 锁文件测试约 31 秒明确返回错误，前一版本的载荷保持不变；随后重试成功。NSIS 卸载器可能复制到临时目录后由子进程继续工作，测试等待子进程实际移除文件，不以启动器退出冒充卸载完成。
- 未覆盖用户现有安装，没有启动真实模型客户端或调用模型，也没有对用户现有数据执行卸载测试。小型载荷不能替代所有机器上对完整安装包的测试，杀毒扫描、磁盘或系统服务故障仍需结合现场详情判断。

## 安装时仍不动

从托盘菜单退出旧版后重试。新版会显示当前步骤；记录最后一条详情以及 `%TEMP%\MirrorNovel-install.log`，可区分进程检查、旧版清理与文件写入阶段。不要直接删除应用数据目录来处理安装文件占用。
